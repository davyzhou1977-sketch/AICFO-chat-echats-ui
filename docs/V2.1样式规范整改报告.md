# AICFO V2.1 样式规范整改报告

整改日期：`2026-03-18`

## 1. 问题说明

- 前端复核发现首轮整改并未完全收口，移动端仍有多处组件继续依赖全局 Less 类名和裸字符串 `className`
- 典型问题包括：
- [apps/mobile-v2/src/app/index.tsx](/Users/zhouhao/Documents/AI_APP/03-AICFO/apps/mobile-v2/src/app/index.tsx)
- [apps/mobile-v2/src/components/mobile/legacy-first-use-coachmark/index.tsx](/Users/zhouhao/Documents/AI_APP/03-AICFO/apps/mobile-v2/src/components/mobile/legacy-first-use-coachmark/index.tsx)
- [apps/mobile-v2/src/components/mobile/legacy-bottom-nav/index.tsx](/Users/zhouhao/Documents/AI_APP/03-AICFO/apps/mobile-v2/src/components/mobile/legacy-bottom-nav/index.tsx)
- [apps/mobile-v2/src/components/mobile/financial-analysis-fusion-legacy/index.tsx](/Users/zhouhao/Documents/AI_APP/03-AICFO/apps/mobile-v2/src/components/mobile/financial-analysis-fusion-legacy/index.tsx)
- 该问题会导致团队在样式文件命名、引入方式和构建约定上继续分叉，也会让后续迭代反复回退到全局类名写法

## 2. 原因分析

- 首轮整改只覆盖了部分组件，没有对移动端相关源码做完整盘点
- 旧版移动端结构沿用过程中，局部样式仍挂在全局 `school-finance-fusion-legacy.less` 下，导致组件层继续直接写字符串类名
- 规范文件虽然写了 `import styles from "./index.less"`，但没有把“禁止裸字符串类名”“全局 less 白名单”写死，执行口径不够硬

## 3. 整改动作

- 已按文件逐项建立问题清单，见 [docs/V2.1-less规范问题清单.md](/Users/zhouhao/Documents/AI_APP/03-AICFO/docs/V2.1-less规范问题清单.md)
- 已将移动端入口页、Coachmark、BottomNav、融合分析页全部改为目录级 `index.tsx` + `index.less`
- 已把上述组件中的本地样式使用方式统一收敛为 `import styles from "./index.less"` + `className={styles.xxx}`
- 已删除旧的业务全局样式文件 [school-finance-fusion-legacy.less](/Users/zhouhao/Documents/AI_APP/03-AICFO/apps/mobile-v2/src/styles/school-finance-fusion-legacy.less)，避免后续误用

- 已将“禁止 `*.module.less` 业务导入”“禁止本地 less 类名写成裸字符串 `className`”写入 [AGENTS.md](/Users/zhouhao/Documents/AI_APP/03-AICFO/AGENTS.md) 和 [项目技术栈与UI规范.md](/Users/zhouhao/Documents/AI_APP/03-AICFO/docs/项目技术栈与UI规范.md)

- `npm run build:web` 通过
- `npm run build:mobile` 通过
- `apps/web-v2/src` 与 `apps/mobile-v2/src` 中未检出 `import styles from "*.module.less"`
- `apps/web-v2/src`、`apps/mobile-v2/src` 与 `apps/mobile-v2/.generated` 中未检出本地 less 类名裸字符串写法，也未检出 `school-finance-fusion-legacy.less` 残留引用
- 样式规范已同步进入长期项目规范文件

## 5. 后续强制要求

- 后续新增局部样式文件时，必须优先创建 `index.less` 或业务语义明确的普通 `.less` 文件
- 引入方式必须写成 `import styles from "./index.less"`
- 使用方式必须写成 `className={styles.xxx}`
- 业务组件中禁止继续直接引入 `*.module.less`
- 业务组件中禁止继续将本地 less 类名写成裸字符串 `className="xxx"`
- 如必须保留全局样式，必须先在规范中注明文件范围和保留原因，并同步更新全局白名单
