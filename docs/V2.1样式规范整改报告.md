# AICFO V2.1 样式规范整改报告

整改日期：`2026-03-17`

## 1. 问题说明

- 前端校验发现当前仓库存在 `*.module.less` 的写法，与项目要求的 `import styles from "./index.less"` + `className={styles.xxx}` 不一致
- 该问题会造成团队在样式文件命名、引入方式和构建约定上出现分叉，不利于长期维护

## 2. 原因分析

- 在 V2.1 首轮实现中，局部样式虽然采用了 CSS Modules 思路，但文件命名仍使用了 `*.module.less`
- 移动端构建配置仍以“全局 less”为默认行为，没有把“局部 less 默认模块化、全局 less 显式排除”这条约束固化到配置层
- 仓库规范文件此前只写了“Less Modules”，没有把文件命名和具体导入代码写死，导致执行口径不够严格

## 3. 整改动作

- 已将业务代码中的实际引入方式统一改为普通 `.less` 命名
- 已将相关组件统一改为 `import styles from "./index.less"` 的引入方式
- 已在 Web 端构建层增加兼容桥接，保证业务源码不再直接依赖 `*.module.less` 写法
- 已将移动端构建配置改为：局部 less 默认走 CSS Modules，仅 `global.less` 与 `school-finance-fusion-legacy.less` 继续保留全局样式
- 已删除移动端残留的旧草稿样式入口文件，避免后续误用
- 已将本次要求写入 `AGENTS.md` 与 `docs/项目技术栈与UI规范.md`

## 4. 验证结果

- `npm run build:web` 通过
- `npm run build:mobile` 通过
- 样式规范已同步进入长期项目规范文件

## 5. 后续强制要求

- 后续新增局部样式文件时，必须优先创建 `index.less` 或业务语义明确的普通 `.less` 文件
- 引入方式必须写成 `import styles from "./index.less"`
- 使用方式必须写成 `className={styles.xxx}`
- 业务组件中禁止继续直接引入 `*.module.less`
- 如必须保留全局样式，必须先在规范中注明文件范围和保留原因
