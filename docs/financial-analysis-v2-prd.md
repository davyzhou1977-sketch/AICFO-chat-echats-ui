# 财务分析 V2 PRD

<p style="color:#dc2626;font-weight:700;">特别提示：人员费用专题要做到可用，必须拿到可解析的工资/补贴明细附件或标准导出表。若附件长期以模糊扫描件为主，系统只能做有限识别，不能直接承诺稳定的人数、人均和结构性统计。</p>

<p style="color:#dc2626;font-weight:700;">特别提示：基本保障专题和 AI 报表查询都高度依赖报销事由、收款单位、报销日期、报销金额、预算项目、申请部门等字段的标准化。若这些字段长期自由填写、缺少清洗规则，统计结果会出现分类漂移。</p>

<p style="color:#dc2626;font-weight:700;">特别提示：当前版本已明确收敛范围，不展示“校长治理”视角，也不输出“内控风险”统计报告。现阶段只做财务分析稳定专题与 Web 端 AI 报表查询。</p>

## 1. 背景

当前系统已经具备传统报销分析能力，能够展示报销金额、报销类别、供应商和大额报销等信息。但现场调研后，客户明确提出两点新的现实约束：

1. “校长治理”视角需要的数据基础过重，短期内不具备稳定实施条件。
2. “内控风险”统计受附件识别精度、合同日期识别、签字清晰度等因素影响，当前不适合直接沉淀为校领导层面的管理报告。

因此，本期版本需要回到更稳妥、可落地的主线：

- 保留原有报销分析能力，并调整为更业务化的“报销行为”
- 新增 4 个与学校经营管理直接相关的财务专题
- 在现有 Web 报销单列表页上增加“AI 报表查询”轻量能力

## 2. 当前版本目标

### 2.1 产品目标

本期财务分析只解决 3 类问题：

1. 学校预算执行是否清楚、及时、可对比
2. 人员费用、基础保障费用、专题投入能否形成稳定统计
3. 列表查询结果能否一键生成图表化汇总报告

### 2.2 页面目标

1. 财务分析页只保留一个主视角，不再切换“校长治理”
2. 首屏默认进入“预算”
3. 顶部只保留一个时间下拉：`本年 / 本季 / 本月`
4. 页面主体采用 5 个并列专题：
   - 预算
   - 报销
   - 人员
   - 保障
   - 专题
5. Web 端报销单列表新增“AI报表查询”，采用右侧抽屉呈现

## 3. 目标用户

### 3.1 校长

更关心：

- 预算执行是否健康
- 人员费用都花到了哪里
- 基础保障费用是否异常波动
- 学生活动、教师成长等专题投入是否清晰

### 3.2 财务负责人

更关心：

- 预算、执行、可用预算是否一致
- 报销结构和费用专题是否可快速汇总
- 查询结果能否即时生成分析图表，减少人工二次出表

## 6. 详细模块设计

## 6.1 专题一：预算

### 6.1.1 管理目标

- 判断预算是否按计划执行
- 判断当前可用预算是否充足
- 从项目和部门两个维度看执行差异

### 6.1.2 首屏核心指标

- 预算金额
- 执行率
- 可用预算
- 项目部门执行率

建议口径：

- 预算金额 = 当前周期预算总额
- 执行率 = 已执行金额 / 预算金额
- 可用预算 = 预算金额 - 已执行金额
- 项目部门执行率 = 按项目与部门交叉聚合后的综合执行率

### 6.1.3 图表建议

图表 1：月度预算执行总览

- 类型：柱线组合图
- X 轴：月份
- 柱：月预算 / 月执行
- 线：执行率

图表 2：项目预算执行对比

- 类型：双柱状图
- X 轴：预算项目
- 系列：预算金额 / 已执行金额

图表 3：部门执行率排行

- 类型：横向柱状图
- 指标：部门执行率

### 6.1.4 项目与部门交叉呈现

移动端不直接展示大二维矩阵，建议采用联动查看：

- 默认展示“项目预算执行对比”
- 用户点击某项目后，下方展示该项目下各部门执行情况
- 或通过轻量筛选器切换到“按部门看项目执行”

### 6.1.5 AI 解读

每个图表卡片下保留 1 张 AI 解读卡，统一三段式：

1. 当前执行现状
2. 偏离计划的风险提示
3. 建议跟进动作

## 6.2 专题二：报销

### 6.2.1 定位

该专题承接上一版已有报销分析能力，名称调整为“报销”，强调报销行为和结构，而不是继续沿用“报销分析”作为产品名词。

### 6.2.2 展示内容

- 报销金额与笔数趋势
- 报销类别结构
- 高频供应商 TOP5
- 大额报销排行

### 6.2.3 管理问题

- 报销金额随时间如何变化
- 报销集中在哪些类别和供应商
- 是否存在集中报销或大额报销现象

### 6.2.4 AI 解读

保留 1 张专题总 AI 解读卡，用于总结：

- 当前报销结构是否稳定
- 是否存在集中度变化
- 财务上值得继续关注的点

## 6.3 专题三：人员

### 6.3.1 管理目标

- 看清人员费用总盘子
- 看清工资、补贴、社保、公积金等费用分别花到哪里
- 让校长能够理解人员费用的结构，而不仅是看到一个总额

### 6.3.2 数据来源

人员专题优先基于以下数据构建：

1. 报销单明细查询结果中，预算项目或项目名称归属于“人员经费”的单据
2. 报销附件中的工资、补贴、社保、公积金等明细表

### 6.3.3 Python 预处理方案

建议单独建设“人员费用预处理脚本”，将附件中的表格数据标准化为中间明细表。

预处理流程：

1. 读取附件
   - Excel：直接解析表头与明细
   - PDF：优先表格抽取
   - 图片：OCR + 表格识别
2. 统一字段
   - 年月
   - 姓名
   - 部门
   - 费用项名称
   - 金额
   - 来源单据 ID
3. 费用类型映射
   - 基本工资
   - 绩效工资
   - 岗位工资/岗位补贴
   - 职务补贴
   - 班主任津贴
   - 出勤奖励
   - 课后服务专项
   - 社保公积金
   - 住房补贴
   - 临聘/劳务
   - 其他
4. 生成透视统计
   - 行：年月
   - 列：费用类型
   - 值：金额汇总

### 6.3.4 图表建议

图表 1：月度人员费用构成

- 类型：堆叠柱状图
- 含义：每月各费用类型的总额与结构

图表 2：重点费用趋势

- 类型：折线图
- 推荐展示：
  - 基本工资
  - 绩效工资
  - 社保公积金
  - 补贴总额

图表 3：当前周期费用结构

- 类型：横向柱状图
- 含义：本期不同费用类型占比

### 6.3.5 首屏核心指标

- 人员费用总额
- 工资总额
- 社保公积金总额
- 补贴津贴总额

### 6.3.6 本期边界

本期人员专题先把“费用类型维度”做深，不把“人员类别人数、人均工资、人均附加成本”作为硬上线目标。

后续如拿到稳定的人员类别主数据，再扩展：

- 在编教师 / 教辅行政 / 外聘教师 / 劳务派遣 / 临聘后勤
- 人数
- 人均费用
- 历年结构变化

## 6.4 专题四：保障

### 6.4.1 管理目标

- 判断学校基础保障费用是否稳定
- 判断水费、电费、物业费、采暖费等是否出现异常变化
- 在不依赖校址、人数、面积等主数据的情况下，先把基础费用趋势看清楚

### 6.4.2 分类口径

首版建议统一清洗为以下保障类别：

- 水费
- 电费
- 物业费
- 采暖费
- 电话网络费
- 安保费
- 保洁费
- 运维服务费
- 其他保障

### 6.4.3 Python 清洗方案

清洗逻辑采用双重校验：

1. 主依据：报销事由关键词
2. 辅依据：收款单位名称

例如：

- 事由包含“水费”，且收款单位为供水相关单位，归入“水费”
- 事由包含“物业”，且收款单位为物业管理单位，归入“物业费”

### 6.4.4 图表建议

图表 1：基础保障月度构成

- 类型：堆叠柱状图
- 含义：各月保障费用构成与总量变化

图表 2：单项保障趋势

- 类型：折线图
- 卡片内切换：
  - 水费
  - 电费
  - 物业费
  - 采暖费

图表 3：当前周期费用结构

- 类型：横向柱状图
- 含义：本期保障费用构成占比

### 6.4.5 为什么不是“一张图全放完”

如果把水费、电费、物业费、采暖费、电话网络费、安保费、保洁费、运维服务费同时放到一张折线图里，移动端可读性会很差，曲线过多也不利于异常识别。

因此首版采用：

- 一张总览构成图
- 一张单项趋势图

这是当前移动端最稳妥的方案。

## 6.5 专题五：专题

### 6.5.1 当前定义

“专题”用于承接学校阶段性重点关注事项，不再用“事业发展”作为固定标题。

首版先定义两个专题入口：

- 学生活动
- 教师成长

### 6.5.2 学生活动专题

管理问题：

- 学生活动经费花了多少
- 活动经费主要集中在哪些类型
- 各月活动投入是否稳定

建议图表：

- 月度活动投入趋势
- 活动类型结构
- 重点活动项目金额排行

### 6.5.3 教师成长专题

管理问题：

- 教师成长投入花了多少
- 培训、研修、讲座、教研补偿分别占多少
- 当前投入是增加还是减少

建议图表：

- 月度教师成长投入趋势
- 教师成长投入结构
- 重点项目金额排行

### 6.5.4 后续扩展

若客户后续更关注食堂，也可以把“食堂运营”纳入专题入口，不需要改动总信息架构。

## 7. Web 端 AI 报表查询

## 7.1 功能定位

AI 报表查询不是新的聊天入口，而是对“当前列表查询结果”的即时汇总能力。

用户先在原有报销单列表页中设置筛选条件，再点击“AI报表查询”，系统将当前结果集自动汇总为轻量图表报告。

## 7.2 入口位置

建议放在现有报销单列表操作区，与以下按钮同层：

- 批量操作
- 导出 Excel
- AI报表查询
- 申请报销

## 7.3 交互方式

采用右侧抽屉，不新开页面。

原因：

- 不打断用户当前查询上下文
- 用户可以一边看列表，一边看汇总结果
- 后续容易增加“复制结论 / 导出图片 / 重新生成”

## 7.4 输出内容

轻量版固定输出：

1. 查询条件摘要
2. 汇总金额
3. 1-2 张自动图表
4. 一句话摘要

## 7.5 图表自动匹配规则

当结果集包含：

- 时间维度 + 一个分类维度：输出分组柱状图 + 折线图
- 只有分类维度：输出横向柱状图
- 只有单一趋势：输出折线图
- 数据过少：只输出汇总卡 + 简表

## 7.6 示例

筛选条件：

- 时间：2026 年 1-3 月
- 校区：西校区、东校区
- 报销事由：水费

建议返回：

- 图 1：东西校区月度水费柱状图
- 图 2：东西校区月度水费趋势图
- 汇总：
  - 西校区总金额
  - 东校区总金额
  - 合计金额
- 一句话摘要：
  - `2026 年 1-3 月水费共 xx 元，其中东校区高于西校区，2 月达到阶段峰值。`

## 10. 三维标签模型（预留）

虽然当前版本不展示“校长治理”视角，但报销单的三维标签模型仍建议继续保留，作为后续专题细分和治理类报表的基础能力。

这三个维度不是当前前端的直接展示主题，而是后续统计口径的预留标签体系：

- 维度 A：资源投向维
- 维度 B：治理方式维
- 维度 C：支出口径维

### 10.1 打标签原则

1. 每张报销单必须同时具备 A / B / C 三个维度标签。
2. 每个维度都采用“一级 + 二级”结构。
3. 维度 A、B、C 各自都必须唯一归类，不允许同一维度下多标签并列。
4. 三个维度之间允许交叉组合，但不能互相替代。
