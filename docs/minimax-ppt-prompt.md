# MiniMax PPT 生成提示词

以下提示词可直接提供给 MiniMax，用于生成一份面向目标客户汇报的高质量 PPT。

---

你是一名顶级 B 端产品方案设计师与演示文稿专家，请基于以下产品背景与需求，生成一份**适合向目标客户汇报的中文 PPT**。  

这份 PPT 的目标不是技术汇报，而是**帮助客户快速理解产品价值、确认需求方向、认可初步设计方案**。  

请严格按照以下要求生成：

## 一、演示文稿定位

- 演示主题：学校财务移动 H5 V2 方案汇报
- 使用场景：面向目标客户进行需求确认和初步方案汇报
- 受众角色：
  - 校长
  - 财务负责人
  - 信息化负责人
- 演示目标：
  1. 让客户理解为什么要做 V2
  2. 让客户理解“财务分析 + 校长治理”双视角的产品价值
  3. 让客户理解 AI 内控分析为什么值得做
  4. 让客户理解当前方案已经形成较成熟的信息架构和页面原型
  5. 为下一步真实数据接入和需求定版创造条件

## 二、整体风格要求

请使用**苹果极简美学**风格设计整套 PPT：

- 视觉气质：高级、克制、现代、干净、专业
- 页面布局：留白充足，信息层级清晰，避免堆砌
- 配色建议：
  - 主色：低饱和蓝色 / 冷灰 / 白色
  - 点缀色：少量绿色或橙色用于强调价值点
- 字体风格：
  - 中文建议偏现代无衬线
  - 标题要有高级感，正文可读性高
- 动效：可有轻微过渡，但不要炫技
- 图表风格：精致、轻量、统一，不要出现粗糙默认样式
- 禁止：
  - 大片廉价渐变
  - 复杂装饰边框
  - 低质图标堆砌
  - 互联网运营风大字报

## 三、内容策略要求

整套 PPT 必须做到：

1. 先讲清楚业务价值，再讲方案结构，再讲页面设计
2. 强调“这不是简单报表，而是管理视角升级”
3. 强调“AI 内控分析”是从审批提示升级为管理报告
4. 强调“校长治理”是从财务控制视角升级为治理视角
5. 所有页面介绍都要突出：
   - 应用名称
   - 核心价值
   - 适用对象
   - 关键界面示意
6. 所有“产品截图”位置请使用**高保真占位框**表示，不要真实生成截图
   - 占位框内统一写：`界面示意占位`
   - 占位框下方写一句说明，例如：`此处展示财务分析页关键界面`

## 四、这次方案的核心产品结构

本次 V2 方案基于现有学校财务移动 H5，新增并优化两个一级视角：

### 1. 财务分析

这是面向财务负责人和校长的“财务控制 + AI 内控分析”视角。

财务分析中有两个子主题：

- 内控风险
- 报销分析

并支持时间筛选：

- 本年（默认）
- 本季
- 本月
- 后续可扩展本学期

#### 财务分析中的“内控风险”包含 4 个模块：

1. AI 内控总览  
用于回答：当前内控风险压力有多大

2. 制度薄弱点  
用于回答：哪些制度问题最容易被反复触发

3. 风险集中在哪里  
用于回答：风险主要集中在哪些部门和业务类型

4. 风险闭环效率  
用于回答：问题发现后有没有被及时整改

#### 财务分析中的“报销分析”包含：

- 报销金额与笔数趋势
- 报销类别结构
- 高频供应商 TOP5
- 大额报销排行

### 2. 校长治理

这是本次 V2 的重点升级视角，目标是帮助校长看到：

1. 学校真正可治理的钱流向哪里
2. 是否花在离学生最近的地方
3. 预算是否真正下沉到基层
4. 是否持续为教师成长与组织内驱力买单

它基于“校长治理财务立方体”模型，包含三个维度：

- 资源投向维：这笔钱最终作用于哪里
- 治理方式维：这笔钱由谁支配
- 支出口径维：这笔钱在校长视角下属于哪种分析口径

校长治理包含 4 个核心模块：

1. 可治理资金总览
2. 离学生最近的资源
3. 基层活力仪表盘
4. 教师成长与激励

## 五、AI 内控分析的关键业务价值

请重点强调以下价值点：

1. 过去系统只能在审批时看到单据级风险提示，现在升级为管理层可读的周期性内控报告
2. 风险主题被统一归类，不再是零散规则提示
3. 可以从校长和财务负责人的视角，看清：
   - 风险是不是越来越多
   - 哪类制度最薄弱
   - 问题集中在哪些部门与业务类型
   - 风险是否真正完成整改闭环
4. 这使财务系统从“报销工具”升级为“治理工具”

## 六、数据底座与实施亮点

请在 PPT 中强调以下“专业可信度”内容：

1. 已形成“规则唯一映射表”
   - 一条规则唯一归属一个风险主题
   - 避免统计遗漏和歧义

2. 已明确业务类型口径
   - 直接使用系统业务类型数据
   - 例如：货物类、服务类、代发劳务费、参加培训/会议、租车费等

3. 已在 PRD 中明确后续真实数据接入所需字段
   - 单据 ID
   - 单据类型
   - 所属部门 / 单位
   - 业务类型
   - 风险主题
   - 风险等级
   - 是否人工干预
   - 整改状态
   - 整改完成时间
   - 退回 / 补件次数

4. 当前方案已经完成：
   - 页面结构设计
   - mock 数据方案
   - 组件化方案
   - 路由和实现基础
   - PRD 文档沉淀

## 七、请生成的 PPT 页数建议

请生成 **8 到 10 页** 的完整客户汇报稿，建议结构如下：

### 第 1 页：封面

要求：
- 标题高级、简洁
- 副标题体现“需求确认与初步方案汇报”
- 页面氛围感强，但不要花哨

建议内容：
- 主标题：学校财务移动 H5 V2
- 副标题：目标客户需求确认与初步设计方案

### 第 2 页：为什么做 V2

讲清楚当前痛点：
- 原系统更偏传统财务控制视角
- 校长缺少治理视角的数据看板
- AI 核查风险目前停留在审批环节，没有沉淀为管理分析能力

### 第 3 页：V2 的整体方案

讲清楚双视角结构：
- 财务分析
- 校长治理

强调：
- 一个统一移动端入口
- 两套管理视角
- 适合企业微信 / 钉钉内嵌 H5

### 第 4 页：应用一 财务分析

必须包含：
- 应用名称：财务分析
- 核心价值说明
- 子主题结构：
  - 内控风险
  - 报销分析
- 右侧或下方放“界面示意占位框”

### 第 5 页：财务分析中的 AI 内控分析价值

重点讲：
- AI 内控总览
- 制度薄弱点
- 风险集中在哪里
- 风险闭环效率

这一页要突出“从审批提示到管理报告”的升级价值。

### 第 6 页：应用二 校长治理

必须包含：
- 应用名称：校长治理
- 核心价值说明
- 4 个治理模块
- “界面示意占位框”

### 第 7 页：校长治理为什么有价值

重点讲：
- 为什么默认看可治理支出池
- 为什么要看资源是否靠近学生
- 为什么要看基层活力和教师成长投入

### 第 8 页：数据底座与专业可信度

重点讲：
- 规则唯一映射
- 业务类型统一口径
- 后续真实数据接入字段

### 第 9 页：当前阶段成果

展示：
- PRD 已形成
- 页面原型和实现方案已形成
- mock 与组件结构已具备
- 已具备进一步接真实数据的条件

### 第 10 页：希望客户确认的关键事项

列出希望客户确认的事项：
- 双视角结构是否认可
- 财务分析中的内控分析是否符合管理诉求
- 校长治理四大模块是否符合校长阅读习惯
- 风险主题映射和业务类型口径是否可按现方案推进

## 八、界面占位框设计要求

每当页面需要展示关键界面时，请使用精致的占位框，而不是随意的灰框。

占位框要求：

- 外观像高保真产品截图容器
- 带圆角、阴影、浅边框
- 内部中央文案统一为：`界面示意占位`
- 下方可附一句小字说明：
  - `此处展示财务分析页关键界面`
  - `此处展示校长治理页关键界面`
  - `此处展示规则映射确认界面`

## 九、输出要求

请直接输出一份完整的 PPT 页面方案，要求：

- 每页都给出：
  - 页面标题
  - 页面核心表达
  - 页面文案内容
  - 页面版式建议
  - 是否需要界面占位框
- 文案风格：
  - 专业
  - 简洁
  - 有管理说服力
  - 不要写得像技术文档

请确保这份 PPT 最终给人的感觉是：

**这不是一个普通报表页面升级，而是一套面向校长和财务负责人的学校财务治理移动方案。**
