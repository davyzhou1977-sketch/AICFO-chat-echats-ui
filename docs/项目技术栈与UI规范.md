# AICFO 项目技术栈与 UI 规范

本文件是当前仓库的正式开发标准。后续所有 Agent、会话、迭代开发、重构与修复任务都必须严格遵守。

## 0. V2.1 定版基线

- 当前项目定版版本为 `V2.1`
- 定版日期：`2026-03-17`
- 当前正式维护的双端目录为：
- `apps/web-v2`
- `apps/mobile-v2`
- `V2.1` 默认作为后续所有需求、修复和回归校验的起点基线
- 除非有新的明确确认，不允许脱离 `V2.1` 已定稿的信息结构、主视觉层级和交互顺序重新设计
- 移动端 `V2.1` 已定稿要求补充如下：
- 页面在常见移动端宽度及较宽嵌入容器下，主体内容应可满屏阅读，不应出现因为主体布局超宽而必须左右滑动查看的情况
- 预算主题首屏预算执行率环图中心，必须同时展示执行率数值和“预算执行率”标签
- Web 与 Mobile 如出现实现分歧，以当前仓库中的 `V2.1` 定稿代码和本规范共同为准

## 1. 总体原则

- 严禁使用 `Tailwind CSS`
- 任何迭代都必须优先保持“上一版最终上传 GitHub 的页面结构、信息层级、交互顺序和文案组织”
- UI 调整必须对照 `docs/web视觉规范(2024).pdf`
- 如当前实现与上一版最终代码或 UI 规范冲突，以“上一版最终代码 + UI 规范”为准
- 不能只修改依赖版本号，必须保证实际开发链路、构建链路和本地预览都可用

- `apps/web-v2`
- `apps/mobile-v2`
- 后续新增版本必须与旧版本做清晰目录隔离，避免混用构建配置和依赖

## 4. 样式规范

### 4.1 Web 端

- 新增样式统一使用 `Less Modules`
- 推荐写法：

```tsx
import styles from "./index.module.less";

<div className={styles.button}>ai报表</div>;
```

- 不允许继续引入新的全局 CSS 方案替代 `Less Modules`

### 4.2 移动端

- 以“上一版已验收结构优先”为原则，允许保留为还原旧版所必需的全局 Less
- 新增局部样式优先使用 Less 文件组织，不允许使用 Tailwind 原子类串联 `className`
- 若引入新样式文件，必须保证命名、层级和复用方式清晰，避免无约束扩散

## 5. UI 与交互规范

- 标签切换按钮、卡片圆角、信息密度、分组间距必须遵循 UI 规范文档，不得主观放大或压缩
- 移动端预算、报销、人员、保障四个主题的结构必须对齐上一版最终实现
- 预算主题首屏必须保留已验收的核心图表结构，例如预算执行率环图、趋势分析图、结构重点图等
- 不允许在未经确认的情况下重做页面头部、首屏 Hero、信息分区或主视觉层级

## 6. 图表规范

- 图表统一使用 `ECharts 4.9.0`
- 图表配色必须在 UI 规范基础上，参考 Web 端蓝青系渐变思路
- 优先使用蓝色、青色、浅蓝色渐变表达主数据、高亮数据和趋势面积
- 图表应避免生硬纯色块，柱形、面积、环图优先加入适度渐变、高光或层次变化
- 图表优化不能改变上一版已经确定的信息结构、指标口径和视觉语义

## 7. 开发验证清单

每次提交前至少完成以下检查：

- `npm run build:web`
- `npm run build:mobile`
- Web 端可访问 `http://127.0.0.1:4174/`
- 移动端可访问 `http://127.0.0.1:4173/mobile/school-finance-fusion-demo`
- 检查是否误引入 `Tailwind CSS`
- 检查是否误升级或替换了规定技术栈
- 检查移动端页面是否出现白屏、资源路径错误、挂载节点缺失、图表未渲染等阻塞问题
- 检查移动端预算首屏在较宽容器下是否仍存在横向滚动
- 检查预算主题环图中心是否仍正确显示预算执行率数字与标签
